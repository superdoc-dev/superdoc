title: 'Review'
description: 'Build your own tracked-change review panel. Accept, reject, navigate next and previous.'

`useSuperDocReview()` exposes a merged feed of comments and tracked changes in document order. Accept, reject, accept-all, reject-all, scroll-to, and next / previous navigation route through `editor.doc.trackChanges.*` underneath.

## A merged feed

```tsx
import { useSuperDocReview, useSuperDocUI } from 'superdoc/ui/react';

export function ReviewPanel() {
  const { items, openCount } = useSuperDocReview();
  const ui = useSuperDocUI();

  return (
    <aside>
      <h2>Review · {openCount}</h2>
      {items.map((item) => (
        <article key={item.id}>
          {item.kind === 'comment' ? (
            <CommentRow comment={item.comment} />
          ) : (
            <ChangeRow
              change={item.change}
              onAccept={() => ui?.review.accept(item.id)}
              onReject={() => ui?.review.reject(item.id)}
            />
          )}
        </article>
      ))}
    </aside>
  );
}
```

`items` is sorted by document position. Each item is discriminated by `kind`: `'comment'` carries the comment, `'change'` carries the tracked change.

## Accept and reject

```tsx
ui.review.accept(changeId);
ui.review.reject(changeId);
ui.review.acceptAll();
ui.review.rejectAll();
```

All four return Document API receipts. After a single decision, the change leaves the live feed (it's been applied or discarded). To render an audit trail, snapshot the change before deciding:

```tsx
const decideChange = (id: string, decision: 'accepted' | 'rejected') => {
  const item = review.items.find((it) => it.id === id);
  const snapshot = item?.kind === 'change' ? item.change : null;

  if (decision === 'accepted') ui.review.accept(id);
  else ui.review.reject(id);

  if (snapshot) {
    setDecided((prev) => [...prev, { id, decision, snapshot }]);
  }
};
```

## Navigate

```tsx
const nextId = ui.review.next();
const prevId = ui.review.previous();
ui.review.scrollTo(itemId);
```

`next` and `previous` walk the merged feed in document order. They wrap. `scrollTo` scrolls the editor viewport to the item's anchor and sets it as the active id.

## Independent vs paired replacements

A typed-over selection in Suggest mode produces an insertion AND a deletion. Default `'paired'` mode collapses them into one review entity (you accept once and both apply). Independent mode gives each half its own id.

```tsx
<SuperDocEditor
  document="/contract.docx"
  modules={{ trackChanges: { replacements: 'independent' } }}
  hideToolbar
  contained
  onReady={({ superdoc }) => setSuperDoc(superdoc)}
/>
```

Pick what your review UI wants to render. One row per replacement (paired) or two rows for the deletion + insertion (independent).

## Highlight the active card

The selection slice exposes `activeChangeIds` and `activeCommentIds`. Use either to highlight the card matching the cursor.

```tsx
import { useSuperDocReview, useSuperDocSelection } from 'superdoc/ui/react';

function ActiveAwareList() {
  const { items } = useSuperDocReview();
  const selection = useSuperDocSelection();
  const activeId =
    selection.activeChangeIds[0] ?? selection.activeCommentIds[0] ?? null;

  return items.map((item) => (
    <div key={item.id} className={item.id === activeId ? 'active' : ''}>
      {/* row */}
    </div>
  ));
}
```

## What the snapshot looks like

| Field | Type | Meaning |
|---|---|---|
| `items` | `ReviewItem[]` | Merged feed in document order. |
| `openCount` | `number` | Open comments + every tracked change. |
| `activeId` | `string \| null` | Active item driven by selection or by `next/previous/scrollTo`. |

`ReviewItem` is a discriminated union: `{ kind: 'comment', comment }` or `{ kind: 'change', change }`. The change shape mirrors `editor.doc.trackChanges.list()`.

## Trade-offs

- Comments interleave ahead of tracked changes within the same block today. The merge is stable but coarse-grained. A finer order lands when `TrackChangeInfo.target` ships.
- Tracked changes in headers, footers, and footnotes route correctly through `scrollTo`. Smooth scroll for those is being threaded as part of [SD-2841](https://linear.app/superdocworkspace/issue/SD-2841); for now they snap.
- `acceptAll` and `rejectAll` apply across every story. To scope to body only, call `accept`/`reject` per id.

# SuperDoc AI Evals

Tests whether LLMs correctly use SuperDoc's document editing tools.

## Quick start

```bash
# 1. Extract tools from SDK (run once, or after tool definitions change)
pnpm run extract-tools

# 2. Set API keys
cp .env.example .env
# Edit .env: OPENAI_API_KEY=sk-...

# 3. Run
pnpm run eval
```

## What it tests

Given a task like "Find the indemnification clause", does the LLM call the right tool with the right arguments?

**26 tests in 2 files:**

- `tool-tests.yaml` (15 tests) -- tool selection, argument structure, correctness rules
- `workflows.yaml` (11 tests) -- find/replace, tracked changes, lists, multi-step, efficiency

Tests validate tool calls (Level 1), not execution results.

## Commands

| Command | What it does |
|---------|-------------|
| `pnpm run eval` | Run all tests against 4 OpenAI models |
| `pnpm run eval:cross` | Cross-provider comparison (GPT-5.4 vs Claude vs Gemini) |
| `pnpm run eval:gdpval` | GDPval: Model+SuperDoc vs Model-Only (~$1-2) |
| `pnpm run eval:view` | Open results in browser |
| `pnpm run eval:repeat` | Run 3x to measure non-determinism |
| `pnpm run eval:export` | Export to results/latest.json |
| `pnpm run extract-tools` | Re-extract tools from SDK artifacts |
| `pnpm run baseline:save <label>` | Save versioned snapshot |
| `pnpm run baseline:compare <a> <b>` | Diff two snapshots |

## How tools are loaded

Tool definitions come from `packages/sdk/tools/tools.openai.json` (generated by `pnpm run generate:all`). The extraction script reads the essential tool list from `tools-policy.json` and writes a subset to `essential.json`.

Run `pnpm run extract-tools` after tool definitions change. Run `pnpm run generate:all` from repo root first if SDK artifacts are missing.

## Writing tests

Tests are YAML in `tests/`. Each test has a task prompt and assertions.

```yaml
- description: 'Find text calls query_match'
  metadata: { category: reading }
  vars:
    task: 'Find where it talks about payment terms.'
  assert:
    - type: tool-call-f1
      value: [query_match]
      threshold: 1.0
```

Use `tool-call-f1` for tool selection, `file://tools/assertions.js:functionName` for argument validation.

## System prompt

`prompts/agent.txt` is a copy of the production prompt from `services/labs-sd-agent/src/features/agent/prompts/system.md`. Update both when changing.

## Caching

Promptfoo caches responses. Same prompt + model = cached. Changing assertions re-evaluates cached responses for free. Clear cache: `npx promptfoo cache clear`.

## Gotchas

- **Anthropic requires `max_tokens`** in provider config
- **`tool_choice: required`** forces tool calls (OpenAI). Anthropic uses `auto`.
- **Tool call output differs by provider.** OpenAI returns arrays, Anthropic returns `tool_use` objects. The `normalize-output.js` transform handles this for cross-provider tests.
- **`essential.json` is 105KB** (~5K tokens per request). Each test sends this.
- **`is-valid-openai-tools-call`** fails on our schemas due to `oneOf`. Use `tool-call-f1` + custom JS instead.
